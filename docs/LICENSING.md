## 検討した点

### 依存先との互換性

| 依存 | ライセンス | GPLv3 との関係 |
|---|---|---|
| NeoForge / Forge | LGPL-2.1 | LGPL-2.1 §3 により GPL(v2 以降)への切り替えが認められている。両プロジェクトとも「Mod は任意のライセンスでよい」という立場。Mod が GPLv3 であることに問題はない |
| night-config(TOML) | LGPL-3.0 | GPLv3 と互換(LGPL-3.0 は GPLv3 への結合を明示的に許可) |
| Gson(テストのみ) | Apache-2.0 | GPLv3 と互換。配布物には含めない |
| Minecraft 本体 | Mojang の EULA | 本体は再配布しない。GPL の Mod は多数存在し、慣行として問題視されていない |

### 難読化との関係
GPLv3 は、頒布するバイナリ(オブジェクトコード)の難読化自体は禁じていません。ただし
**対応するソース一式(ビルドスクリプトを含む)を提供する義務**があります。したがって:
- 難読化は「配布する jar」にだけ適用し、ソースとビルド手順は公開する(M4 でビルドに統合)。
- 難読化ツールはビルドに必要なものとして公開できる(オープンソース)ものを選ぶ。
  (ProGuard は GPL-2.0-or-later だが、出力物にはライセンスが及ばない例外がある。)

### セキュリティ設計との整合
ソース公開・フォーク自由は、このプロジェクトの前提(**秘密は鍵にのみ置く**。`THREAT_MODEL.md` 参照)と整合します。
GPL の改変版がチート業者に作られても、サーバーは **作者が署名した公式ビルド一覧** に無いビルドを拒否できます。
つまり「ソースは自由、公式ビルドとして認められるのは署名されたもののみ」という運用です。

### `or-later` について
`GPL-3.0-or-later` は将来の GPL 版への移行余地を残す標準的な指定です。
「v3 のみ」に固定したい場合は、SPDX ヘッダと本ファイルを `GPL-3.0-only` に変更してください
(現在の著作権者は 1 人なので、この変更はいつでも可能です)。
